## Step 1 — Ask for the target board

If the user hasn't specified a board, ask: **"Is this for a Seed or Field project?"** (or another board if context suggests it). The board controls which example pool to draw from and which `--board` flag `helper.py` needs.

## Step 2 — Pick the closest existing example

Prefer **`copy`** over **`create`** whenever a close match exists — it gives working code to start from rather than a blank template.

### Seed examples (`seed/`)

| Example | What it does |
|---|---|
| `Blink` | LED blink — minimal hardware init, no audio, no DSP. Bare-bones starting point. |
| `Button` | GPIO input — reads a switch with debounce, drives an LED. |
| `bypass` | Audio passthrough — `memcpy` of input to output. Simplest possible audio callback. |
| `Drum` | Rhythm machine — two `Switch` inputs trigger kick/snare via `Oscillator`, `WhiteNoise`, and `AdEnv`. |
| `DSP` | Minimal DSP scaffold — audio callback with DaisySP included but nothing wired. Blank audio template. |
| `Knob` | ADC potentiometer reading — maps a knob to LED brightness via `hw.adc`. |
| `OLED` | SSD1306 128×64 display over 4-wire SPI — `OledDisplay` driver with cycling messages. |
| `Osc` | Single oscillator with envelope — `Oscillator` + `AdEnv`, button-triggered. Classic synth voice skeleton. |
| `USB_MIDI` | USB MIDI note-on handling — `MidiUsbHandler`, single `Oscillator` voice tracks the most recent note. |
| `WavPlayer` | WAV file playback from SD card — `SdmmcHandler`, `FatFSInterface`, `WavPlayer`. Requires SD card wiring. |
| `Logger` | UART serial logging — `hw.Print` / `hw.PrintLine`, log buffer overflow handling. Good for debugging. |
| `QSPI` | QSPI flash — waveform table stored in external flash (`DSY_QSPI_BSS`), played back via `Phasor`. |
| `Ram` | SDRAM validation — large buffer in SDRAM (`DSY_SDRAM_BSS`), read/write speed benchmark. |
| `SDMMC` | SD card via FatFS — file create/read/write cycle, blinks LED on success. |
| `USB_CDC` | USB CDC serial — echo-back of received bytes over USB virtual COM port. |
| `ReceiveTest` | USB receive stress test — records incoming USB bytes and echoes them back. |
| `LCD_HD44780` | HD44780 character LCD over GPIO — 4-bit parallel interface, text display. |
| `HWTest` | Hardware validation suite — SDRAM, audio I/O, and peripheral smoke tests. |

### Field examples (`field/`)

| Example | What it does |
|---|---|
| `chorus` | Stereo chorus — `Chorus` module, knobs control delay time and LFO rate with slew smoothing. |
| `flanger` | Flanger effect — `Flanger` module, knobs map to delay, feedback, LFO depth/rate. |
| `phaser` | Phaser effect — `Phaser` module, knobs control frequency, LFO rate, stage count, wet/dry. |
| `KeyboardTest` | Polyphonic keyboard — 16-voice `Oscillator` pool driven by the Field's capacitive keyboard. |
| `Midi` | Polyphonic MIDI over TRS — 16-voice class with `Oscillator` + `Adsr`, handles note-on/off/CC. |
| `modalvoice` | Modal synthesis keyboard — `ModalVoice` physical model, keyboard selects scale pitches, knobs control timbre. |
| `stringvoice` | String synthesis keyboard — `StringVoice` Karplus-Strong model, same scale layout as `modalvoice`. |
| `Nimbus` | Granular clouds processor — port of Mutable Instruments Clouds, 10 parameter pages, SDRAM grain buffers. Complex multi-file project. |
| `sampler` | 8-voice recorder/player — `SampleBuffer` in SDRAM (`DSY_SDRAM_BSS`), keyboard triggers per-voice record and playback. |

## Step 3 — Run the correct command

### Copy an existing example (preferred)

```bash
python helper.py copy <board>/<NewProjectName> --source <board>/<SourceExample>
```

What `copy` does:
- Duplicates all source files into the new directory
- Renames files and replaces all internal text references (`SourceExample` → `NewProjectName`)
- Deletes stale `build/` and `vs/` directories
- Skips `.ai` and `.png` files

### Create from the blank board template

Use this only when no existing example is close enough:

```bash
python helper.py create <board>/<NewProjectName> --board <board>
```

What `create` generates in the new `.cpp`:
- Correct `#include "daisy_<board>.h"` and `#include "daisysp.h"`
- Board-specific hardware class (`DaisyField hw;`, `DaisySeed hw;`, etc.)
- Audio callback with proper signature and `hw.ProcessAllControls()` for boards that need it
- `hw.Init()`, `hw.SetAudioBlockSize(4)`, `hw.SetAudioSampleRate(...)`, `hw.StartAudio(AudioCallback)`

**Board-specific notes generated by `create`:**
- `seed`: no `hw.ProcessAllControls()` in callback, uses `hw.Configure()` before `hw.Init()`
- `patch`: 4-channel audio callback instead of 2
- `patch_sm`: uses `OUT_L[i]`/`OUT_R[i]` macro style instead of `out[n][i]`

### Update debug resources (optional, after either command)

```bash
python helper.py update <board>/<NewProjectName>
```

Regenerates `.vscode/` launch and IntelliSense configs from the current template.
